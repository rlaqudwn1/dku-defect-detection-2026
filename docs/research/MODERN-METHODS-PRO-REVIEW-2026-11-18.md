# 현대적 방법·라이브러리 Pro 검토와 후속 계획안

2026-11-18. GPT-6 / Pro는 전송 전 UI에서 확인했다. 검토된 메타프롬프트v0.2로 같은 대화에 후속 요청하고, 이번 요청에 연결된 완료 응답을 회수했다. HTML·표15개·출처를 비공개 원문에 보존했다. 이 문서는 Pro의 자문과 진행자의 제한된 대조를 정리한 **후속 계획안**이며, 최종 모델 채택·대회 실험·독립 문헌 전수감사 완료가 아니다.

## 1. 현재 판단

기존 [연구 계획](RESEARCH-PLAN-2026-11-18.md)의 관측 규약 조정→실제 입력 정보보존→관계·평가 계약은 유지한다. 추가240장 판독·여러 모델·모든 초기화 대조를 의무 목록으로 늘리지 않는다. 현재 계획을 검토한 snapshot과 당시 원문은 동일 바이트이며, 메타프롬프트v0.1→v0.2를 연구 계획 자체의 수정 이력으로 기록하지 않는다.

| 항목 | Pro 권고 | 현재 지위 |
|---|---|---|
| 우선 구성 | DINOv3 ViT-S/16 동결 CLS 특징 + 선형1-logit BCE head | 첫 검증 가설. 미구현·실제 학습 전 |
| 대체 구성 | torchvision ConvNeXt-Tiny IMAGENET1K_V1의 동결 pooled 특징 + 선형 head | 자산·호환성·자원 탈락 시 조건부. 성능으로 교체하면 비교/선택 예산에 포함 |
| 추가 비교 | 국소 attention 집계 또는 제한 FT 또는 대체 표현 | 관측에 따라 하나씩. 총 구성 최대3개이며 다 채울 의무 없음 |
| ResNet18 | I/O·저장·점수 계약의 구현 기반으로 유지 | 장기 scratch 대회 학습을 필수 선행으로 두지 않음 |
| 정상 전용·생성 증강·불균형 처리 | 별도 질문이 생길 때만 | 현재 필수 비교에서 제외 |
| 도구 | 기존 PyTorch/torchvision/NumPy 중심 경로를 좁게 확장 | Anomalib/Lightning/timm/Transformers 도입을 최신성만으로 결정하지 않음 |

동결은 encoder를 고정하고 이미지 라벨0/1로 마지막 분류기만 적합한다는 뜻이다. 자기지도 사전학습 표현을 써도 이 후속 학습은 두 클래스 라벨을 쓰는 지도 분류다. CLS는 이미지 전체의 특징이며, 실제 국소 결함 정보를 충분히 담는지는 미확인이다.

## 2. 먼저 할 작업과 분기

1. 기존48장·지정16장의 원응답을 보존하고,9건 조정과 가독성 정의 차이를 해결 또는unknown+이유로 닫는다. 정의가 바뀐 항목만 재확인한다.
2. 실제 전처리에서 원본 범위·resize·pad·가시성을 확인한다.256/384/512는 후보이며 최적값이 아니다. 공식 모델의 center crop을 현재resize+pad에 조용히 대입하지 않는다.
3. 관계·노출·평가 목적을 확인한다. 필요한 split 변경과 실제 그룹 경계는 별도 검토한다.
4. 정확한 encoder 코드·weight 출처/버전/공개일/라이선스/전체SHA-256, 실제 Colab Python/GPU/driver/wheel을 확인한다. 아직 가중치 취득·설치·GPU 실행은 하지 않았다.
5. 우선 표현의 개발용 입력에서 특징 추출·head 적합·시간/메모리·cache·저장/재개를 짧게 확인한다. pilot에서 validation 점수를 보고 후보를 바꾸면 그 노출도 선택 이력으로 기록한다.
6. 성능 비교 전에 자원·구성·선택 횟수·반복/불확실성·의미 있는 차이의 기준을 고정한다. 총 구성 최대3개 안에서 필요한 질문만 비교한다.

| 관측 | 다음 행동 |
|---|---|
| 원본에서도 단서 불명 | unknown 유지. 큰 입력·FT가 정답을 만든다고 가정하지 않음 |
| 변환에서 단서 소실 | 입력/범위/tile부터 수정. MIL·FT로 지워진 픽셀을 복구한다고 쓰지 않음 |
| 정보는 보존되나 국소 증거가 중요 | 같은 encoder의 국소 집계 검토. CLS→patch는 특징 종류도 달라짐 |
| 입력·분할 계약 확인 후 표현 적응 부족 가설 | 학습된 head에서 시작하는 제한 FT 한 종류 검토. 성능 저하만으로 원인을 확정하지 않음 |
| 자산·호환성·자원 실패 | 검증된 대체안 검토 |
| 일반화 목표를 지지할 관계/주석 부족 | 더 큰 모델보다 주장 범위를 줄임 |

## 3. 실제 코드와 연결할 제약

진행자는 다음을 현재 코드에서 직접 대조했다.

- `engine._validate_dataset`은 train∪validation=전체 학습CSV를 요구한다. 별도 확인용 3-way holdout을 예약한다면 데이터·분할 계약 수정이 필요하다. 수정 전 2-way 검증 성능은 모델 선택 성능으로 한정한다.
- `data.make_split`은 정상·불량이 섞인 supplied group을 거부한다. 실제 관계를 보존해야 하면 분할기부터 설계·검토하고 그룹 분해·relabel로 우회하지 않는다.
- `engine._model`은 provenance 필드·기재 날짜·로컬 파일 hash를 검사한다. 공개일·라이선스 사실 자체를 자동으로 외부 검증하는 기능은 아니다.

Pro가 제안한 구현 범위는 encoder adapter, 전처리/patch geometry 명세, frozen encoder eval·gradient off와 head 적합 분리, cache와 변경 spec의 재개 거부, 추출/평가 device 명시다. **아직 적용하지 않았다.** 특징 cache에는 원본·ID순서·partition·encoder commit·weight hash·변환·특징/집계·dtype/shape·환경을 연결하고 fit 요소는 train ID만 사용한다.

평가는 이미지당 점수 하나와 전체 validation의 AUROC를 유지한다. 한 클래스뿐인 slice의AUROC는 정의 불가다. 위치 정답 없이 pixelAUROC·AU-PRO를 만들지 않는다. 같은validation의 선택 편향을 seed 반복만으로 없앨 수 없다.

## 4. 문헌·라이브러리 확인 범위

Pro는 DINOv3 원문 일부·고정 공식 코드, 산업 전이의 반대 근거, MIL 원방법, LP-FT 연구와 정확 라이브러리 릴리스를 연결했다. 전체 문헌 주장·버전·출판 상태의 독립 재감사는 남아 있다. 외부 성능 수치는 우리 성능이 아니다. Pro 응답에 기재된BibTeX 후보는 확인 후 보고서 참고문헌에 편입하며 기존 목록을 자동 교체하지 않는다.

진행자는 [고정 DINOv3 hubconf](https://github.com/facebookresearch/dinov3/blob/6876159a11b4df116f30f667f8c9888617df0751/hubconf.py)에서 `dinov3_vits16` 경로와torch/numpy 의존성을 확인했다. [해당 라이선스](https://github.com/facebookresearch/dinov3/blob/6876159a11b4df116f30f667f8c9888617df0751/LICENSE.md) 원문 일부도 대조했지만 대회 적격성·전체 법률 검토 완료를 뜻하지 않는다. [PyTorch2.15 공식 릴리스](https://github.com/pytorch/pytorch/releases/tag/v2.15.0) 앞부분에서CUDA13.2/13.4 wheel 언급을 확인했다. 상세GPU요구조건·호환성·실제 실행은 확인 전이다.

`requirements-verified-cpu.txt`는 과거CPU 환경 목록이며 Colab GPU lock이 아니다. 최신 버전·설치 가능성과 실제 호환/재개 성공을 구분한다. 두 가중치 후보의 파일명 짧은 해시는 전체SHA-256이 아니며, 허용 가중치 gate는 아직 통과하지 않았다.

## 5. 보존·완료 범위

Pro 대화 링크는 비공개 전송 기록에 보존한다.

비공개 원문/영수증: `runs/method-modernization-review-2026-11-18/`. 원문HTML·변환본·정확turn결속·패킷23/23감사·전송프롬프트·직접 확인 범위를 보존한다. Pro의 `modern-method-plan-20261118.json`은 파일 링크만 보존했으며 파일 자체는 회수·검증하지 않았다.

완료한 것은 **Pro 검토 의뢰·회수와 후속 계획안 정리**다. 새 이미지 관측·기존 라벨 대조·모델/분할 채택·가중치 다운로드·새 라이브러리 설치·대회 학습·성능 측정·원격 영속 저장·새 환경 복구 완료가 아니다. 기존 연구 단계는 승격하지 않는다. 다음 최소 작업은 CAL48 관측 규약 조정이며, 새 비교·자산·split 채택 시 해당 대상 버전의 검토를 남긴다.
