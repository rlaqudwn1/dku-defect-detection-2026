# 현대적 방법·라이브러리 연구 의뢰 메타프롬프트 v0.1

작성일: 2026-11-18. 상태: 로컬 검토 전 초안. 아직 GPT Pro에 전송하지 않았다. 이 문서는 연구 의뢰문이며 모델 채택·실험 완료·성능 결과가 아니다.

---

당신은 산업 이미지 결함 탐지의 연구 설계자이자 비판적 페어리뷰어다. 첨부한 로컬 계획을 먼저 검토하고, 현대적인 방법과 라이브러리로 실행할 수 있는 수정 계획을 작성하라. 단순 최신 모델 목록이나 기존 계획에 대한 동의는 필요하지 않다. 사용자의 해석과 진행자의 판단, 이전 Pro의 권고를 모두 검증 대상 가설로 취급하라. 답변은 한국어로 하되 핵심 용어는 짧게 설명하라.

## 1. 입력과 현재 상태

대상 저장소는 https://github.com/rlaqudwn1/dku-defect-detection-2026 이다. 기준 commit은118f4578a4395f7885c3fd8f4ca87c87d683e7b8이며 로컬 미커밋 변경이 있다. 원격 저장소 연결을 가정하되 원격 HEAD가 첨부와 같다고 가정하지 마라. 정확히 첨부한 파일·버전과 접근 가능 여부를 먼저 밝히고 첨부를 현재 로컬 상태의 기준으로 삼아라. 판정마다 파일/라인/코드조각 또는 문서 절을 인용하라. 접근하지 못한 자료를 읽었다고 쓰지 마라.

- 문제: 정상0/불량1의 이미지 단위 지도 이진 분류. 복수 제품이어도 이미지당 불량 점수 하나를 출력하며 전체 validation 예측의 AUROC로 평가한다. sigmoid 점수의 확률 보정은 미확인이다.
- 학습10821장: 정상9621/불량1200. 테스트800장. 제품군 정답·결함 위치/유형 정답·실물 전후 쌍·촬영 그룹·최종 일반화 목표는 미확인이다.
- 기존 전수 카탈로그·과거 디코드/바이트 중복 기록이 있다. 픽셀/근접 중복과 촬영 독립성은 미확인이다. 기존 증거의 범위가 맞으면 재사용하라.
- 16층 고정240장에 보정48장이 포함된다. 첫48장과 그 일부16장의 기술 관측을 보존했으며 자국 후보 차이9건과 가독성 정의 조정이 남아 있다. 별도 발견29장은 미판독이다. 관측은 실제 결함 정답이나 새 학습 라벨이 아니다.
- 현재 코드는 전체 이미지 ResNet18, 기본 scratch, BCEWithLogits, AdamW, resize+pad, sigmoid 점수를 구현했다. 합성 CPU 기능 검사만 있고 대회 데이터 학습·성능 비교는 없다. ResNet18은 단순 기준선 후보이며 현대적 주력 방법으로 선정하지 않았다.
- 다음 로컬 작업은 관측 규약 조정→실제 입력 변환의 정보보존 조사다. 기존 분할기는 mixed-label 그룹을 거부하므로 관계가 확인되면 수정·검토가 필요하다. 그룹을 쪼개거나 라벨을 바꾸어 우회하지 마라.
- 무료 Colab 우선, 가벼운 Python 실행기, W&B 선택 연결이다. GPU·시간·메모리 예산은 미측정이며 임의 수치를 실제 관측값으로 채우지 마라.

## 2. 이번 조사에서 결정할 질문

1. 현재 계획의 질문·관측·평가·모델 비교 흐름은 타당한가? 유지/수정/삭제/보류를 구분하고 최소 수정안을 먼저 제시하라.
2. 이 데이터와 감독 조건에서 어떤 현대적 사전학습 표현·적응·이미지/국소 집계 방법을 우선 비교해야 하는가? 기존 ResNet18 구현을 유지·축소·건너뛸 조건도 설명하라.
3. 정상 전용 이상 탐지는 제공된 불량 감독을 쓰는 접근과 무엇이 다른가? 모두 같은 backbone에 억지로 맞추지 말고 원인 해석 비교와 실용 비교를 구분하라.
4. 일반화의 대상을 새 촬영·새 실물·새 제품 범주·미지 결함으로 나누고 현재 확인 가능한 범위와 불가능한 범위를 구분하라. 데이터 관계 미확인을 특정 목표가 충족됐다는 근거로 사용하지 마라.
5. 필요한 현대적 라이브러리·도구는 무엇이며 현재 경량 코드에 어떻게 통합할 것인가? 기존 구현 재사용과 신규 의존성의 효용·비용·대안을 비교하라.

## 3. 문헌·기술 조사 기준

이전 넓은 모델 조사와 EDA 방법론 조사를 출발점으로 재사용하고 빠진 결정 근거를 조사하라. 2025·2026의 관련 연구와 유지보수되는 공식 구현을 포함하되 최신 연도나 leaderboard 순위를 채택 이유로 삼지 마라. 최종 비교표는 핵심 후보 최대6개로 좁히고, 그중 첫 실행 후보를 더 작게 선택하라. 이 수는 성능이나 통계적 충분성을 보장하는 값이 아니라 조사 범위 제한이다.

- 핵심 주장에는 원논문/부록/저자 공식 코드/공식 문서를 연결하라. 검색 결과 요약·블로그·이전 Pro 응답은 원문 증거로 대체하지 마라.
- 발표일·확인한 판·학회/저널/프리프린트 상태·실제 읽은 절·확인하지 못한 내용을 표시하라. 초록 확인·원문 일부·실행 재현을 구분하라.
- 감독량, 추가 데이터, backbone/해상도, fitting 범위, 평가 단위, 분할·선택 예산이 다르면 성능 수치를 공정 비교라고 쓰지 마라. 외부 benchmark 성능은 우리 성능이 아니다.
- 각 권고에 우리에게 적용할 이유, 반대 근거/실패 조건, 더 싼 대안, 아직 필요한 관측을 제시하라. 조사한 결과보다 판단 강도를 높이지 마라.
- 라이브러리는 이름만 나열하지 말고 공식 저장소·정확 릴리스/버전·라이선스·유지보수 확인일·Python/PyTorch/CUDA 호환 근거·필요 기능을 확인하라. 미확인 호환성을 보장하지 마라.
- 가중치는2026-11-15까지 공개된 정확 버전·출처·라이선스·SHA-256을 사용 전에 확인해야 한다. 검색으로 해시를 확인하지 못하면 미확인으로 두고 로컬 확인 절차를 제안하라.

## 4. 경계

원본 이미지/CSV/제공 라벨 수정, 테스트 정답·외부 원본 데이터/라벨 조회, 외부 실제 이미지 추가 학습, 원격 모델 API 대회 예측을 금지한다. 사용자 설명상 연구용 이미지의 LLM 제공과 LLM 생성 증강은 허용되지만 공식 규정 원문 독립 확인과 구분한다. 이번 요청에는 원본 이미지를 첨부하지 않는다. 이미지를 봤거나 데이터를 실제 분석했다고 하지 마라. 테스트 의미 판독·정답 추정·의사라벨 생성을 제안하지 마라. GPU 결제·제출·학습·가중치 다운로드는 이번 조사 범위가 아니다.

생성 증강은 초기 필수 단계가 아니라 실제 원본 검증과 학습 전용 참조 분리를 갖춘 조건부 비교로 다뤄라. 데이터 증강/정상 감소를 불균형 비율만으로 우선 처방하지 마라.

## 5. 요청 산출물

A. 가장 중요한 반론과 계획 수정안: 쟁점/현재 근거/판정/바꿀 결정/미확인.
B. 후보 비교표: 연구 질문/방법/감독·데이터/근거 원문/공식 구현/라이브러리·가중치 상태/비용 근거/실패 조건/우선순위.
C. 최소 실험 계획: 단계별 가설·변경 변수·고정 조건·학습/검증 적합 범위·전체 AUROC 및 보조 지표·자원 측정·중단/승격 조건·보고서 주장 한계. 현대적 표현 비교와 같은 backbone의 초기화 비교를 구분하라.
D. 구현 계획: 현재 모듈을 재사용/수정/추가할 범위, 의존성 변경, provenance·split·전처리·checkpoint·저장/재개 연결, 우선순위와 확인 명령. 코드를 실행했다고 쓰지 마라.
E. 역할 분담: Pro가 맡을 문헌/설계 판단, 로컬이 확인할 해시·호환성·실험·이미지 관측, 독립 검토가 필요한 결정. 같은 조사를 반복하지 않도록 완료 조건을 제시하라.
F. 보고서 연결: 지금 쓸 수 있는 문장과 향후 결과가 필요한 주장, 참고문헌 카드와 BibTeX 후보, 검색 경로·선정/제외 이유·누락 범위.

마지막으로 실행 우선안 하나와 그 선택을 바꿀 관측을 제시하라. 불확실한 전제를 숨겨 정답 모델 하나를 단정하지 마라. 긴 일반론보다 결정에 필요한 근거를 우선하라.

## 6. 전송 패킷 초안

첨부 예정: 현재 연구 계획, 진행 원고, 주장 장부, 출처 역할/BibTeX, 기존 논문 안내·최신성 점검·EDA 계획, baseline 설정과 engine/data의 관련 전체 코드, pyproject. 이전 Pro 응답 두 건은 같은 대화에서 참조하되 접근 불가 시 필요한 원문을 별도 첨부한다. 실제 전송 전에 정확한 목록·크기·해시·민감정보 제외·첨부 확인을 수행한다. 원본·비공개 매핑·장부·자격증명은 넣지 않는다.
