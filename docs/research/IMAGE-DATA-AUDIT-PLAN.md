# 제품 불량 이미지 데이터 조사 계획

기준일: 2026-11-17. 상태: 조사 설계 제안. 실제 데이터 조사·모델 성능·분할 타당성의 완료 보고가 아니다.
기존 [가설·데이터 설계](../HYPOTHESES-AND-DATA.md)를 구체화하며, 실행과 기록은 [운영 진입점](../OPERATIONS.md)을 따른다.

## 1. 질문과 판단 기준

목표는 데이터가 어떤 조건에서 정상·불량을 구별하게 하는지, 어떤 검증이 타당한지, 모델 입력에서 무엇을 보존해야 하는지를 근거로 정하는 것이다.

| 연구 질문 | 확인할 증거 | 바뀔 결정 |
|---|---|---|
| 라벨 하나가 이미지의 무엇을 뜻하는가? | 공식 설명, 정상/불량 학습 표본, 복수 제품·가림·판독 불가 사례 | 이미지 단위 학습 목표와 라벨 한계 |
| 작은 결함이 입력에 남는가? | 원본 확대와 실제 resize/pad/crop 결과 비교 | 해상도·비율 보존·크롭 도입 여부 |
| 반복 촬영이나 유사 이미지가 있는가? | 해시, 유사 후보 쌍, 사람이 확인한 관계와 불확실성 | 분리해야 할 그룹과 검증 대상 |
| 배경·제품 종류·크기가 라벨과 얽히는가? | 라벨별 카탈로그 통계와 시각 판독 | 비교할 하위 집단과 단서 의존성 진단 |
| 제공 train/test 입력 형태가 다른가? | 라벨을 쓰지 않은 크기·화질·구성 요약 | 전처리 스트레스 검사와 대표성의 한계 |

모든 질문은 관측/가설/미확인을 구분한다. 파일명으로 실제 제품 ID나 촬영 순서를 확정하지 않는다. 이미지당 출력은 anomaly_score 하나이며, 사진의 제품 수와 무관하다.

## 2. 현재 근거와 구현 범위

공개 기록에는 11,621장 전수 디코드, 손상 0, 바이트 중복 0, 최대 36장의 시각 표본 조사가 있다. 이는 과거 기록이며 이번 계획에서 원본을 재검증한 결과가 아니다. 픽셀 중복·근접 중복·촬영 관계와 검증 대표성은 미확인이다.

현재 `profile`은 원본 해시, 크기/모드/EXIF, RGB 평균·표준편차, 디코드 오류와 36장 표본 시트를 생성한다. 아래의 판독 장부, 픽셀/pHash 조사, 변환 비교, 그룹 근거, 표본 추정은 추가 작업이다. 현재 `split`은 바이트 중복과 전달된 그룹을 묶지만, 서로 다른 라벨이 들어 있는 그룹은 거부한다. 실제 촬영 그룹은 정상·불량을 함께 포함할 수 있으므로 이 제약이 적용되면 그룹을 쪼개거나 라벨을 바꾸지 않고 분할기 확장을 별도로 검토한다.

기존 지속 연구 장부 위치와 단계별 현재 유효성은 unknown이다. 이번 설계의 기록은 과거 연구 상태를 재구성하지 않는다.

## 3. 단계 0 — 입력과 조사 규약 고정

- 기존 비공개 manifest/profile/split과 원본의 존재·해시·생성 코드 버전을 확인한다. 동일 데이터·코드·검사 범위의 유효한 결과는 재사용하고 달라진 부분만 재검사한다.
- 공식 라벨 정의와 허용 범위를 적고, 모르는 촬영 과정·제품 개체·결함 위치의 출처는 unknown으로 둔다.
- 카탈로그 ID, 원본 SHA-256, 판독 양식 버전, 표본 시드, 변환 버전, 조사자와 시각을 기록한다.
- 이미지·CSV 원본은 읽기 전용으로 취급한다. 파생물과 로그는 Git에서 제외된 실행 디렉터리에 저장한다.
- 통계·표본·판독·그룹·분할·결정은 별도 파일로 둔다. 원래 라벨을 조사 태그로 덮어쓰지 않는다.

완료 조건: 모든 조사 결과가 정확한 입력과 조사 규약으로 연결되고, 누락 근거가 명시된다.

## 4. 단계 1 — 전체 이미지의 구조와 품질 조사

전체에 대해 CSV 대응·유일 ID·라벨·파일 해시·완전 디코드·방향·모드를 확인한다. 정규화한 방향/RGB 픽셀의 해시는 크기와 변환 규약을 함께 식별해 바이트 중복과 구분한다. 색상 변환·라이브러리 버전을 기록한다.

크기·비율·파일 바이트·평균/대비·밝기와 과노출/저노출 후보·흐림 후보를 요약한다. 흐림 지표는 표면 텍스처에 민감하므로 이상 후보를 찾는 데만 사용하고 이미지 삭제 기준으로 쓰지 않는다. 먼저 기존 카탈로그로 가능한 통계를 만들고 추가 지표는 질문에 필요할 때 계산한다.

train은 라벨별 개수와 비율을, test는 무라벨 입력 특성만 요약한다. 다수 클래스 전체 평균이 소수 클래스의 문제를 가리지 않게 라벨별·크기별 표를 함께 만든다. 크기 차이만으로 제품·결함 분포 차이나 인과관계를 단정하지 않는다.

완료 조건: 전수 검사 항목마다 검사 수·실패 수·미검사 수와 사례 ID가 남는다. 품질 이상 후보의 실제 확인 여부가 분리된다.

## 5. 단계 2 — 시각 조사와 표본 설계

### 판독 기준부터 맞추기

작은 보정 표본으로 용어·확신도·판독 환경을 맞춘다. 예: 24~48장. 이는 계획용 시작 규모이며 통계적 충분성을 의미하지 않는다. 축소 시트는 탐색용이고 판독은 원본 확대를 포함한다.

태그 예: 보이는 제품 구성, 단일/복수/불명, 배경·조명·반사·가림, 보이는 결함 후보의 위치/모양/대략적 크기, 판독 가능/불가, 확신도와 이유. 눈에 안 보이는 결함을 정상이라고 판정하지 않는다. 조사용 위치는 검증된 결함 마스크가 아니다.

### 빈도 추정 표본과 문제 발견 표본

- 빈도 추정: train에서 라벨·크기/비율을 기준으로 고정 시드 확률 표본을 뽑는다. 초기 예산 예시는 240장이다. 희소 층은 전수로 보고, 실제 층 수와 판독 시간에 맞춰 규모를 조정한다.
- 불량을 많이 뽑았다면 단순 합계로 전체 비율을 말하지 않는다. 전체 빈도에는 층별 모집단 비율을 적용하고, 층별 결과·불확실성·분모를 함께 낸다.
- 문제 발견: 저품질 극단값, 희귀 구성, 유사 후보, 판독 불일치 등을 추가로 고른다. 선정 이유를 남기고 확률 표본과 혼합해 발생률을 추정하지 않는다.
- 층별 모집단 수·표본 수·포함확률을 저장한다. 클래스/층을 불균등 추출했다면 전체 빈도는 설계 가중치를 반영하고, 단순 표본 비율과 구분한다.
- 먼저 원래 라벨·모델 점수·파일명 단서를 가리고 시각 특징을 기록한 뒤 라벨과 대조한다. 판독 불가/정보 부족을 허용한다.
- 독립 판독자는 고정 무작위 재판독 부분과 중요 불일치 후보를 각각 확인한다. 두 부분의 불일치율을 따로 보고하며, 합의 과정에서도 최초 응답을 보존한다. 두 AI의 동의는 실제 결함 정답의 검증을 대신하지 않는다. 실제 재료/결함 전문가가 참여하지 않았다면 그 한계를 적는다.

test에는 정상·불량 판독 라벨이나 의사 라벨을 만들지 않는다. 입력 형태의 제한된 기술 조사만 수행한다. 원격 시각 모델 API로 판독·예측을 요청하지 않는다.

완료 조건: 표본별 추출 이유·확률·판독 범위·미확인이 연결되고, 비율 추정과 사례 발견을 구분해 설명할 수 있다.

## 6. 단계 3 — 관계와 누수 조사

1. 바이트 중복 → 규약을 고정한 픽셀 중복 → pHash 등 시각 해시 → 필요 시 허용된 로컬 encoder의 이웃 검색 순서로 후보를 넓힌다.
2. 각 방법의 상위 후보, 임계값 주변, 후보 밖 무작위 쌍과 서로 다른 검색법이 놓친 쌍을 조사한다. 합성 resize/재압축/작은 이동도 검색 점검에 쓸 수 있지만 실제 중복 전체의 탐지율을 보증하지 않는다.
3. 쌍별로 같은 원본의 변형/같은 촬영 개체 후보/같은 제품 종류만 유사/무관/판단 불가를 구분한다. 임계값과 확인 근거를 보존한다.
4. 확인된 관계를 그룹으로 제안한다. 연쇄 연결로 서로 다른 개체가 하나의 큰 그룹이 되는지, 경계 쌍·큰 그룹·라벨 혼합 그룹을 검토한다. 판단 불가 관계는 억지로 확정하지 않는다.
5. 분할 후보를 만든 뒤 split 경계를 넘는 이웃을 다시 검사한다. 탐지 방법·검토 범위 내의 결과만 보고하며 '누수 없음'을 무조건 보증하지 않는다.

제품 종류와 촬영 개체는 다르다. 새 촬영 개체 일반화를 평가하면서 제품 종류 전체를 반드시 holdout해야 하는 것은 아니다. train/test 유사성이 발견돼도 test 답을 추정·조회하거나 train 라벨을 복사하지 않는다.

encoder는 2026-11-15까지 공개된 정확한 버전·출처·라이선스·SHA-256 확인 후에만 사용한다. 도구의 기본 모델 자동 다운로드는 사용하지 않는다. 데이터에서 PCA/정규화 등을 fitting한다면 학습 부분만 사용하며 test 적응과 구분한다. 2D 임베딩 그림은 탐색 자료이고 촬영 개체 증거가 아니다.

완료 조건: 확인/기각/미확인 관계, 후보 생성 범위, 그룹 규칙, 남은 누수 위험을 제시한다.

## 7. 단계 4 — 입력 변환에서 정보 보존 조사

동일한 학습 표본에 원본 확대, 비율 유지 resize+pad, 전체 resize, 후보 crop을 실제 학습/추론과 같은 코드로 적용한다. 예를 들어 256/384/512를 비교 대상으로 검토하되 GPU 예산과 시각 관측 후 후보를 줄인다. 특정 크기를 미리 적절하다고 확정하지 않는다.

원본에서 결함 후보를 확인할 수 있는 경우 위치·대략적 폭을 조사 태그로 기록하고, 잘림/형태 왜곡/미세 정보 소실/패딩 비율을 확인한다. 변환의 기하학적 좌표·면적 검사는 사람의 가시성 판독과 구분한다. 원본에서도 판독 불가한 경우 변환 성공으로 세지 않는다. 재현 가능한 표본·순서와 판독 조건으로 비교하며 사람에게 보인다는 이유만으로 모델 학습 가능성을 보증하지 않는다.

뒤집기·회전·색변화·블러·지우기·무작위 crop은 라벨 의미를 보존하는지 개별 조사한다. 특히 이미지의 불량 부분이 사라진 crop에 부모의 불량 라벨을 자동 부여하지 않는다. 복수 제품에서는 이미지 단위 집계 문제도 남는다.

완료 조건: 후보별 확인 수·정보 손실 사례·불명 사례와 첫 입력/증강 후보의 선정 이유를 제시한다. 학습 효과는 후속 비교 실험으로 확인한다.

## 8. 단계 5 — 검증 프로토콜과 첫 진단 실험으로 연결

- 일반화 대상을 한 문장으로 정한다. 예: 관측한 제품 구성에서 독립 촬영 개체에 대한 정상·불량 순위 예측. 실제 개체 정보가 없으면 후보 그룹의 불확실성을 그대로 남긴다.
- 그 대상에 맞춰 그룹 경계를 우선하고 클래스 수·독립 그룹 수·크기/제품 구성·품질 층의 검증 포함 여부를 확인한다. 모든 층 비율을 기계적으로 같게 맞추지 않는다.
- 기존 20% split은 후보일 뿐이다. 비율·seed는 성능이 좋아 보이는 것을 골라 확정하지 않는다. 새 제품 일반화는 필요한 경우 별도의 스트레스 평가로 구분한다.
- 구조·관계 조사 후 holdout을 고정하고, 의미적 탐색·튜닝은 development 부분에 집중한다. 사전 조사에서 살핀 데이터 범위도 기록한다. 이미 상세히 판독한 표본을 새 seed로 다시 나눠도 완전히 미관측인 검증이 되지는 않는다. 가능하면 별도 최종 확인 부분을 두되 독립 양성 그룹 수·예산을 먼저 확인한다. 불가능하면 반복 선택 편향의 한계를 명시한다.
- AUROC는 전체 검증 예측에서 계산한다. 두 클래스가 없는 slice에는 AUROC를 만들지 않는다. 양성 이미지 수만이 아니라 독립 양성 그룹 수를 기록하고, 종속성을 반영한 paired 비교/불확실성 방법을 실행 전에 정한다. 보편적인 최소 표본 수나 고정 오차를 가정하지 않는다.
- 이미지 크기·색상 등만 이용한 작은 진단 모델은 단서 의존성 후보를 찾는 후속 실험이다. 높은 점수는 결함 원인이나 편향의 확정 증거가 아니다. 저주파·배경 등 통제 실험은 추가 가설로 구분한다.
- baseline의 미학습 예측으로 불일치 후보를 찾을 수 있다. 모델과 라벨이 다르다는 이유만으로 정답을 수정하거나 표본을 제외하지 않는다. cleanlab도 선택적 후보 정렬 도구이며, 분할 종속성을 지킨 out-of-sample 예측을 사용한다.

완료 조건: 데이터 관측 → 그룹/분할 → 전처리 → 제한된 첫 실험의 연결을 독립 검토자가 추적할 수 있다. EDA와 작은 진단 baseline은 반복하되 전체 조사 완료를 가장하지 않는다.

## 9. 산출물·예산·중단 기준

비공개 산출물: 카탈로그, 질문별 표, 추출 manifest, 원본/변환 비교 시트, 판독 원문, 유사 쌍·그룹 근거, 미확인 목록, 후보 split·protocol, 결정과 다음 실험 카드. 원본·이미지 시트·개별 ID·라벨·예측은 공개 Git에 넣지 않는다. 공개 문서는 방법과 허용된 집계·한계만 담는다.

CPU 중심으로 기존 카탈로그와 작은 판독 표본부터 시작한다. 판독 처리량을 짧게 측정한 뒤 다음 배치와 독립 검토 예산을 정한다. 임베딩은 값싼 조사로 남은 질문을 해결하지 못할 때 추가한다. 표본 확대는 새 패턴·불일치·미확인 비율과 결정 영향에 따라 정하며, 새 패턴이 안 나왔다는 이유로 희귀 문제 부재를 주장하지 않는다.

데이터 담당은 카탈로그·판독·관계, 평가 담당은 일반화 대상·분할·선택 편향을 맡는다. 진행자가 채택/보류 이유와 남은 한계를 적고, 별도 검토자가 입력·관계·분할·변환 결정을 검토한다. 이번 호출의 모델/effort를 미래 연구 하네스 기본값으로 복사하지 않는다.

첫 실행 묶음: 기존 근거 해시 확인 → 질문별 전수 요약 → 판독 기준 보정 → 고정 표본/문제 발견 표본 → 변환 비교와 관계 후보 조사 → 검토 후 다음 배치 결정. 긴 학습·GPU 결제·대회 제출은 포함하지 않는다.

## 10. 방법론 참고자료와 근거의 한계

- [Datasheets for Datasets](https://arxiv.org/abs/1803.09010): 구성·수집 과정·용도 등을 명시하는 데이터 문서화의 원문 제안. 원문 초록의 제안 범위를 확인했다. 문서 작성만으로 품질이나 성능이 보장되지는 않는다.
- [Shortcut Learning in Deep Neural Networks](https://arxiv.org/abs/2004.07780): 표준 벤치마크에서 통하지만 더 어려운 조건에 전이되지 않는 규칙을 설명하는 관점 논문. 원문 초록 범위를 확인했다. 우리 데이터에 실제 shortcut이 존재한다는 증거는 아니다.
- [scikit-learn: grouped cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data): 그룹을 split 사이에 공유하지 않는 평가와 클래스 비율 고려 방법의 공식 문서. 실제 그룹을 발견하거나 대표성을 보장해 주지는 않는다.
- [FiftyOne Brain](https://docs.voxel51.com/brain/index.html#near-duplicates): 이웃·근접중복과 split 누수 후보 탐색의 공식 기능 문서. 임계값과 encoder에 따라 오탐·누락이 달라진다. 초기 필수 의존성은 아니며 기존 Python/CSV/로컬 시트로 시작한다.
- [cleanlab filter](https://docs.cleanlab.ai/stable/cleanlab/filter.html): 라벨 문제 후보와 out-of-sample 예측 권고의 공식 문서. 라벨 오류의 확정 판정·원본 수정 절차로 사용하지 않는다.

기능 설명은 제작자 공식 문서에 대한 A급 근거로 취급한다. 논문의 문서화 제안과 관점은 방법 설계의 근거이며, 이 프로젝트에서의 개선 효과를 입증한 실험 근거는 아니다. 2025/2026 이미지 품질·근접중복·감사 문헌 검색도 수행했으나, 최신 연구라는 이유로 원격 판독이나 새 대형 모델 도입을 결정하지 않았다. ACM/Nature 출판사 본문은 접근 제한이 있어 저자 arXiv 초록과 접근 가능한 공식 문서를 사용했다.
