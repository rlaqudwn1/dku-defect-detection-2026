# 무료 Colab 충분성 판단

사용자는 무료 Colab을 사용한다. 현재 데이터 규모만으로 시작은 가능할 것으로 보는 설계 판단이며, 실제 할당 GPU와 모델 실행을 측정하기 전에는 대회 전체에 충분하다고 확정하지 않는다.

## 관측한 사실

원본 11,623개 파일의 합계는 약 1.94GB다. 학습 이미지 10,821장과 테스트 800장이 있다. JPEG SOF 헤더로 확인한 크기별 개수는 `data/manifests/image-profile.json`에 보존했다.

- 학습: 약 150만 픽셀의 직사각형, 8종 크기. 가장 많은 크기는 1500×1000(3,502장).
- 테스트: 304×304 462장, 288×288 264장, 608×608 62장, 615×615 12장.
- 모든 파일에서 SOF의 구성요소 수는 3이다. 이는 실제 픽셀의 색상 모드 판독과 구분한다.

학습/테스트의 해상도·비율 차이가 있다. 테스트가 학습 이미지의 크롭인지 축소본인지, 어떤 제품인지 추정으로 확정하지 않는다. 작은 결함이 저해상도 전처리에서 사라지는지 학습 데이터로 조사한다.

## 공식 운영 제약

무료 Colab은 GPU 종류·가용 시간·할당을 보장하지 않으며 최대 실행 시간도 사용 패턴과 가용성에 영향을 받는다. 세션은 종료될 수 있다. 여러 작은 파일을 Drive mount에서 반복 읽기보다 ZIP을 VM에 복사해 로컬에 푸는 방식을 사용한다. [Google 공식 FAQ](https://research.google.com/colaboratory/faq.html).

## P000: 처음 측정할 것

1. GPU 이름·VRAM·CPU/RAM·빈 디스크·Python/패키지 버전을 기록한다.
2. ZIP 복사·압축 해제 시간을 측정하고 파일 해시를 검증한다. ZIP과 해제 데이터의 공존 공간, 체크포인트 공간을 확보한다.
3. 첫 후보 모델로 실제 학습·검증 epoch를 실행한다. 초기화/워밍업 시간과 정상 epoch 시간을 나눠 기록한다.
4. 입력 크기·배치별 시간, 처리량, peak GPU memory를 W&B에 기록한다. OOM은 실패 run으로 남긴다.
5. checkpoint 저장 후 새 프로세스/새 세션에서 재개하고 고정 가중치 평가를 확인한다.
6. 관측 시간으로 후보 수·epoch·seed·추론 시간을 포함한 전체 예산을 계산한다. GPU가 바뀌면 재측정한다.

## 판단과 대응

- 실행이 메모리에 맞고 한 실험을 충분한 여유로 마칠 수 있으면 무료 Colab에서 baseline과 작은 순차 비교를 진행한다.
- 메모리가 부족하면 배치를 먼저 줄이고, mixed precision·입력 크기·모델 크기를 검토한다. 성능 영향을 기록한다.
- 실행은 가능하지만 가용 GPU 시간이 반복 실험을 막으면 후보 수·seed/fold 수부터 줄이고 epoch 경계 재개를 사용한다.
- 최종 재현 리허설도 진행하기 어려우면 유료/별도 GPU 대안을 사용자와 검토한다. 결제는 자동 진행하지 않는다.

Colab 성능 수치, GPU 할당, 모델 AUROC는 아직 측정하지 않았다.
