# Pro 최초 분석과 로컬 EDA 실행·재개 계획

상태: 실행 가능한 파일럿 계획. 이미지 분석·Pro 전송·연결 성공·성능 개선을 아직 주장하지 않는다. 조사 내용은 [이미지 조사 계획](research/IMAGE-DATA-AUDIT-PLAN.md), 전체 연구 단계는 [PLAN](PLAN.md), 실행·기록 규칙은 [OPERATIONS](OPERATIONS.md)를 따른다.

## 목적과 역할

비싼 추론을 현재 에이전트와 Pro가 반복하지 않도록 근거가 준비되는 시점에 Pro를 첫 분석자로 쓴다. 로컬 Python은 정확한 계산, 진행자는 근거 준비·코드 실행·검증·기록, Pro는 질문별 해석과 실험 제안, 별도 검토자는 중요한 판단을 맡는다. 매번 7개 도메인을 모두 호출하지 않는다.

이번 파일럿 목표는 ChatGPT 웹 GPT-6 Pro다. 요청·화면 관측·독립 provider 영수증은 구분한다. 역할별 모델/effort 기본값은 null이며 이번 구축 자문에서 사용한 Astra high를 미래 기본값으로 복사하지 않는다. 웹 내부 토큰·비용을 관측하지 못하면 null이다. 기존 비교 자료가 없을 때 절감률을 만들거나 같은 분석의 A/B 재호출을 의무화하지 않는다.

## 단계와 병렬 가지

[실행 계획 JSON](../configs/pro-assisted-eda.json)이 단계 ID·의존성·완료조건·다음 행동의 기계 판독 기준이다.

| 단계 | 산출물·완료조건 요약 | 선행 |
|---|---|---|
| P00 새 세션 | 이전 인계 탐색, 과거 unknown, 코드/계획/범위 고정 | 없음 |
| P01 입력 확인 | 원본·기존 manifest/profile/split의 존재·해시·실패 | P00 |
| P02 Pro 경로 확인 | 연결·로그인·UI 모델/Pro 확인, provider 증명과 구분 | P00 |
| P03 텍스트 패킷 | 질문·규칙·코드·테스트·해시와 전송 전 내용 검토 | P00 |
| P04 로컬 EDA·표본 설계 | 검사 분모·통계·확률/발견 표본 분리, 독립 검토 | P01 |
| P05 Pro 텍스트 분석 | 실제 패킷·대화·원문·시간·사용량 관측 | P02,P03 |
| P06 파일럿 판단 | 별도 검토·쟁점 처분·계속/범위조정/보류 | P05 |
| P07 시각 자문 허용 | 공식 규정 근거·허용 범위·별도 검토 | P00、선택 |
| P08 시각 표본 준비 | 허용된 학습 소량 표본과 전체/확대/변환 연결 | P04,P07、선택 |
| P09 시각 자문·대조 | 실제 응답·ID 검사·원본 대조·별도 검토 | P02,P06,P08、선택 |
| P10 다음 실험 결정 | 관계·분할·전처리 근거와 제한 실험 카드·별도 검토 | P04,P06 |

P01/P02/P03은 병렬로 준비할 수 있다. 로그인이나 Pro 응답을 기다리는 동안 P01/P04를 진행한다. P07~P09는 선택 가지이며 허용 미확인은 완료가 아니다. 시각 자문을 쓰지 않으면 local_only 결정과 한계를 남긴다. 사용했다면 P10 완료 기록에 최신 P09 완료 record의 고정 refs를 추가한다. 현재 코드가 조건부 의존성을 자동 추론하지 않으므로 진행자와 검토자가 이 조건을 확인해야 한다.

텍스트 패킷은 공개 코드·문서만 사용한다. 이미지 자문은 외부 서비스·원본/파생 이미지·조사 태그 사용의 공식 허용을 확인한 뒤 진행한다. 웹 사용을 원격 모델 API 금지의 자동 예외로 간주하지 않는다. test 정답·점수·의사 라벨을 만들지 않는다. 원본·모델·개인 경로·비공개 장부는 패킷에 넣지 않는다.

## 재개 명령

실제 비공개 장부 위치를 먼저 확인한다. 아래 위치는 새 파일럿에서 사용할 수 있는 예시이며 과거 장부의 위치를 뜻하지 않는다.

```bash
.venv/bin/defectlab workflow configs/pro-assisted-eda.json runs/pro-assisted-eda/ledger.json
```

`workflow`는 읽기 전용이다. 전문가·Pro·브라우저를 호출하거나 장부를 생성하지 않는다. 없는/빈 장부에는 history unknown과 기존 인계 확인/새 세션 명시 행동을 반환한다. 기존 장부가 없다면 사용자 요청으로 시작하는 이번 세션임을 `record`로 명시한다. 과거 완료 단계를 역으로 만들어 넣지 않는다.

출력의 `ready_steps`는 지금 착수하거나 재판정할 수 있는 병렬 작업, `next_step`은 그중 필수 단계 우선 권고다. 단계마다 historical_status, validity, readiness, blocked_by, reasons, next_action을 확인한다. 모든 필수 단계가 현재 유효하게 완료돼야 complete가 true다. 선택 단계의 생략을 성공으로 기록하지 않는다.

완료 record는 다음을 만족해야 한다.

- `kind=stage`, `stage_id`는 JSON의 단계 ID, `status=completed`, `validity=current`, 정확한 `workflow_plan_sha256`.
- 계획의 completion_conditions와 실제 파일 evidence. JSON 기록 입력은 기존 `record` 계약을 사용한다.
- 실제 request/execution과 해당 실행을 참조하는 decision. 로컬 명령도 실제 호출 handle/영수증과 결과 파일을 사용하고 모델 관측은 null로 둔다.
- 선행 단계들의 **최신 완료 record ID/해시**를 refs/depends_on 경로에 고정한다.
- requires_review 단계는 별도 호출·서로 다른 작성/검토자·고정 대상 evidence의 review와 이를 사용하는 decision을 연결한다.

기록의 존재는 과학적 충분성이나 허용 규정의 진위를 자동 검증하지 않는다. 완료조건의 내용은 진행자/검토자가 판단한다. 원문 응답 수신·독립 검토·채택·실행·저장·원격 영속화·새 세션 복구는 별개다.

실패/중단은 기존 ID와 파일을 보존하고 새 시도 ID를 만든다. 입력·계획·검토 대상이 달라지면 이전 완료를 자동 승계하지 않는다. 계획 해시는 JSON 파일 바이트 기준이며 변경 시 재판정한다. 새 선행 record를 만들면 후속 완료가 이전 버전만 참조하는지도 검사한다. 관계없는 과거 실패나 낡은 파일 하나로 모든 단계를 무효화하지 않는다.

## 첫 오프라인 텍스트 파일럿

질문: 정상·불량이 섞인 실제 촬영 그룹을 현재 split이 거부할 때, 원본 라벨·그룹 관계를 보존할 변경과 검사는 무엇인가? 이는 알려진 제약의 분석 파일럿이며 새 버그 발견 성능 시험이 아니다.

```bash
.venv/bin/python scripts/prepare_pro_packet.py \
  configs/pro-pilot-packet.json runs/pro-assisted-eda/packet-text-001
```

[패킷 명세](../configs/pro-pilot-packet.json)는 정확한 텍스트 파일 허용 목록, 질문, 규칙, 완료조건, 출력 계약을 가진다. 생성 결과는 source 사본, line 번호가 있는 evidence.md, prompt.md, hash manifest다. 기존 출력 디렉터리는 덮어쓰지 않는다. source의 상대 경로·허용 위치·확장자를 검사하고 symlink·runtime·데이터·가중치를 제외한다.

이 도구는 secret detector가 아니다. 허용된 코드/문서 안에도 민감정보가 있을 수 있어 **정확한 목록과 내용을 확인한 뒤** 전송한다. 생성은 prepared일 뿐 전송 허가·실제 Pro 호출·모델 확인·독립 검토를 뜻하지 않는다. 반환 응답은 원문 그대로 새 파일로 저장하고 실제 전송 패킷 hash와 대화 handle을 연결한다. 전송 직후 중단되면 재전송 전에 기존 대화·응답을 확인해 중복 호출을 피한다.

초기 예산은 분석 1회와 필요한 증거 보완 최대 1회다. 응답에는 결정 제안, path:line 근거, 가설/unknown, 대안 최대 3개, 다음 실행 최대 3개를 요구한다. 긴 내부 사고 과정이나 재요약 호출을 요구하지 않는다. 실제로 관측한 준비·회수·검토 usage, 사람 개입 시간, 경과 시간, 자료량, 추가 왕복, 근거 오류와 채택 전 수정량을 남긴다. 실용적인 절감 목표는 비교 근거를 확보한 뒤 실행 전에 고정한다.

## 이번 구현에서 실행할 범위

세션 기준과 공개 코드 패킷을 고정하고 로컬 원본/기존 근거의 가용성을 확인하는 단계부터 시작한다. 패킷과 상태 조회의 재실행·stale 검사를 검증한다. Pro 연결이 안 됐거나 공식 허용이 없다는 상태를 숨기지 않는다. GPU 학습·결제·대회 제출·무인 재질의·브라우저 강제 종료는 자동 실행하지 않는다.

세션 종료에는 비공개 handoff에 실제 장부 위치·해시, 최신 단계 record와 유효성, 남은 의존성, 다음 최소 행동을 기록한다. 영속 저장 요청과 목적지 해시 확인·복구 성공을 구분한다.

## 첫 표본 설계

P04의 구체 규약은 [첫 EDA 표본과 판독 규약](research/EDA-FIRST-LOOK.md) 및 `configs/eda-first-look.json`을 따른다. 보정48을 포함한 고정240과 별도 발견 후보를 먼저 준비한다. 명부·빈 양식 생성과 실제 이미지 판독 완료를 구분하며, 판독 결과를 본 뒤 고정 명부를 교체하지 않는다.
