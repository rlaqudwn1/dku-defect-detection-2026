# Astra 리뷰 후속 설계 추적

원본 검토는 [Astra 전체 리뷰](2026-11-17-astra-high-review.md)다. 검토 기준은 `7f3fc1b`이며, 아래는 진행자가 그 지적에 대응해 구체화한 설계다. **설계 반영과 구현·검증 완료를 구분한다.** 원래 검토가 최신 설계의 독립 검토로 자동 승계되지는 않는다.

| 지적 | 설계의 대응 위치 | 아직 필요한 증거 |
|---|---|---|
| F01 가설이 실험을 통제하지 않음 | 가설·데이터 문서의 반증 예측·판정·다음 행동, 백로그의 선행 연구 단계 | 실제 첫 가설과 실행 전 계획 |
| F02 파일 무결성과 EDA/의미 검증 구분 | 전수 디코드·카탈로그·질문별 조사·관측/불확실성 | 전체 CPU 검사·시각 표본·결정 연결 |
| F03 검증 대상·그룹 근거 미정 | 평가 대상 문장·그룹/파생물·fitting scope 계약 | 실제 그룹 근거·split 검사 |
| F04 첫 가중치 규정 근거 | 첫 모델/encoder에도 동일 확인, 카드의 날짜 표현 통일 | 실제 모델·가중치 출처/조건·해시 |
| F05 이미지 단위 입력/출력 | 전체 이미지 기준안·크롭의 약한 라벨 문제·평가 경로 계약 | 모델 head/loss/변환 설정과 ID/점수 검사 |
| F06 최적화·복구 세부 미정 | 단일 모델 수직 구현 전에 실제 baseline 설정과 복구 상태를 정함 | 선택한 optimizer·scheduler·AMP·유효 batch, 중단/재개 비교 |
| F07 카탈로그·캐시 식별 계약 | 데이터 계층과 encoder/전처리/순서/fitting scope 식별 | 실제 캐시가 필요할 때 생성·무효화 검사 |
| F08 튜닝 공정성·예산 정산 | 운영 문서의 시간/예약 분리, 비교 목적·자원/학습 기회 기록 | P000·후보별 측정·사전 선택 규칙 |
| F09 반복 holdout 선택 | 작은 튜닝 전 확인 정책과 선택 횟수·한계 기록 | 실제 최종 확인 방법과 변동/한계 |
| F10 ensemble 선택·재학습 관계 | 구성원 전처리·집계 순서·선택 횟수·전체 재학습 구분 | 고정 recipe와 독립 재현 |
| F11 선택 기록 ignore 위험 | 작은 결정·영수증을 추적되는 management 기록에 두는 안 | 저장 위치 확정·git 추적 검사; ignore 수정은 미실행 |
| F12 세션 종료·업로드 위험 | 영속 저장/복구 상태와 관측 구간·영수증 설계 | 실제 원격 완료/hash·새 세션 복구 |
| F13 재현 합격·이식성 | 측정 방법과 최종 추론 경로의 허용오차 확인, 세 수준 재현 | 환경·선택 버전·새 세션 실행 기록 |
| F14 마감·리허설 위험 | 첫 baseline 직후 리허설, fallback·탐색 중단 목표 | 실제 fallback과 최신 제출 안내 |
| F15 주장·실패·관측 계보 | 보고서 계획의 주장 ID/입력/표본/관측/해석/한계 | 실제 결과·실패·주장 대조 |

현재 어떤 지적도 기능 검사나 실제 실험 완료만을 근거로 닫지 않았다. F04의 날짜 문구 수정처럼 문서 자체의 변경은 확인할 수 있지만, 사용할 가중치의 규정 적합성은 후보 선정 뒤 확인해야 한다.

## Astra medium 설계 리뷰 후속

[한 차수의 설계 리뷰](2026-11-17-astra-medium-design-review.md)는 요청한 Astra medium으로 수행됐다. 검토 대상 파일들의 hash는 원문 보고서에 있다.

- D01: 첫 입력/출력·최적화·선택·재개 항목을 [첫 실행·재현 계약](../FIRST-RUN-AND-REPRODUCTION.md)으로 구체화하고 계획·실험 카드에서 연결했다.
- D02: 같은 문서에 코드/dirty 변경·환경·상대 경로·개인 인증 없는 전달·불필요한 pretrained 재다운로드 방지·실제 검사 범위를 추가했다.
- D03: 검토가 필요 없는 작업은 사유와 함께 decided/completed로 이동하며 reviewed를 거치지 않는다고 명시했다.

이는 리뷰 뒤의 설계 수정이다. 변경 후 별도 재검토는 하지 않았으며 `changed_after_review; not_rereviewed` 상태로 남긴다. 실행 코드·환경 묶음·실제 시험으로 지적을 닫았다는 뜻은 아니다.
