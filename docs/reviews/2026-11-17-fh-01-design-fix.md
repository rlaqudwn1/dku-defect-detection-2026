# FH-01 설계 수정과 수용 시나리오

대상: [최종 전체 계층 리뷰의 중간 지적 FH-01](2026-11-17-astra-medium-final-hierarchy-round-1.md). 해당 리뷰 원문과 당시 판정은 보존한다. 사용자가 이후 이 지적의 수정을 요청하여 설계 문서만 보완했다.

## 수정 범위

- [관리 하네스 §5.1](../MANAGEMENT-HARNESS.md#51-루트-단계의-근거와-변경-시-재판정): 단계 근거·변경 전파·진행자 재판정의 책임과 시점.
- [공통 기록 규약](../harness/RECORDS.md#루트-단계-판정): task/decision/증거 버전과 변경·유효성·후속 작업 연결.
- [전체 계획 §11](../PLAN.md#11-구현-순서와-판단-시점): 단계 진행 조건이 이 루트 판정에 연결됨을 명시.

상태는 설계 반영이다. 실제 단계 집계·변경 감지·재판정 실행기를 구현하거나 실행 검사한 것은 아니다.

## split v1 → v2 수용 시나리오 — 실행 이력이 아닌 문서 예시

가정: C 기준 실험이 split v1의 task/결정/평가 증거로 완료됐고, 후속 비교 계획과 보고서 초안이 이 근거를 참조한다. 이후 확인된 촬영 종속 관계 때문에 split v2를 만들 필요가 생겼다.

| 시점 | 진행자의 판정·기록 | 다음 행동·담당 |
|---|---|---|
| 변경 전달 | 데이터 담당이 split v1→v2, 관계 근거·이유·영향 후보를 전달 | 진행자가 변경 ID와 의존 관계를 확인 |
| 영향 표시 | A2의 분할 근거, C와 그 결과를 참조하는 후속 비교/선택·관련 보고서에 needs_reassessment 표시. split v1의 완료 run과 점수는 그대로 보존 | 데이터/평가 담당은 새 분할을 확인; 모델 담당은 새 baseline 필요성을 정리 |
| 재판정 | 진행자가 새 분할 기준으로 A2/C 완료 조건을 대조하고, C의 v1 점수를 v2의 완료 근거로 재사용하지 않는다고 결정. 필요한 새 baseline task와 담당·미완료 의존성을 연결 | 새 split의 baseline/평가를 확보하기 전까지 그 결과에 의존하는 성능 채택은 보류 |
| 독립 작업 | 원본 파일 무결성 증거·재사용 가능한 공통 코드·관련 없는 Related Work 초안 등은 실제 영향이 없는 경우 유지 | 해당 작업 담당은 계속 진행; 전역 롤백을 하지 않음 |
| 새 근거 확보 | 새 task/평가가 완료 조건을 충족하면 진행자가 v2 근거로 새로운 단계 판정. 이전 판정과 supersedes 관계를 기록 | 현재 단계 요약·다음 작업·관련 원고를 새 근거에 맞춰 갱신 |

이 시나리오에서 현재 유효한 근거와 미완료 의존 작업·담당자가 드러나며, 과거 완료는 삭제되거나 새 기준 완료로 둔갑하지 않는다. 실제 그룹·분할·baseline이 현재 만들어졌다는 뜻은 아니다.

## 확인 범위

문서 간 연결, 변경 영향과 책임·시점, 과거 근거 보존, 독립 작업 지속을 확인할 수 있는 설계 사례다. 모델 학습·GPU 사용·데이터 변경·코드 구현은 하지 않았다. 집중 재검토 결과는 별도 기록한다.
