## 확인한 설계 경계

- CCDS는 폴더 역할 참고이며 완성된 학습 코드베이스 도입으로 표현하지 않는다. 라이브러리·trainer·첫 비전 모델은 미정으로 유지한다.
- 공통 데이터·학습·평가·추론 경계는 책임 구분이다. 단일 모델의 전체 실행 경로부터 만들고 별도 프레임워크·registry 서버·과도한 추상화를 요구하지 않는다.
- 모델 명세, pretrained, run, 재개 checkpoint, 추론 가중치, 평가, ensemble, 최종 선택을 구분한다. 변경 가능한 alias를 최종 식별자로 쓰지 않으며 재학습 모델에 이전 검증 점수를 직접 복사하지 않는다.
- W&B 산출물과 Git의 작은 기록, Drive 복구본의 역할은 기존 계약과 일치한다. 기록 경로·스키마·ignore 확인은 구현 전 결정할 항목으로 명시돼 있다.
- 가중치 저장·학습 종료·평가·복구·플랫폼 선택은 서로 다른 증거다. 현재 모델·계정 연결·재현 성공이 있다는 주장은 없다.
- 대회 비전 모델 관리와 자문 에이전트의 LLM 배정이 분리돼 있다. 현재 구축 작업의 모델 배분을 미래 하네스 기본값으로 옮기지 않는다.
