# 메타 하네스 설계 자문 요약 — 2026-11-17

이 문서는 진행자가 실제로 받은 세 자문 응답을 요약한 기록이다. 원본 호출 영수증이나 모델/effort 실행 증명은 아니다. 자문은 설계만 읽었으며 도구·계정 연결·학습·Colab 관측은 수행하지 않았다.

## 호출 범위

기획 v0.1(`7f3fc1b`)과 Astra 전체 리뷰를 읽고, 사용자가 요청한 도메인별 조언·페어리뷰·연구 시간·Colab 관리에 대해 자문했다. 호스트가 제공한 task handle은 다음과 같다.

| 관점 | 호스트 task handle | 결과 |
|---|---|---|
| 연구 방법론·데이터·검증 | `/root/research_harness_advice` | 자문 응답 수신 |
| 연구 시간·Colab 운영 | `/root/operations_harness_advice` | 자문 응답 수신 |
| 페어리뷰·결정 절차 | `/root/pair_review_harness_advice` | 자문 응답 수신 |

이 자문에 별도 모델/effort override를 요청하지 않았다. 실제 런타임 모델/effort에 대한 독립 영수증은 제공되지 않았으므로 기록하지 않는다. 이후 사용자가 지정한 현재 구축 작업의 모델 배분은 이 과거 자문의 실행 기록을 소급 변경하지 않는다.

## 연구 방법론 자문

상주 에이전트 조직보다 고정한 연구 산출물을 필요한 역할에 보내는 작은 구조를 권했다. 먼저 가설을 관측·가정·반증 예측·비교·자원 한도로 구체화하고, EDA가 분할·전처리 선택을 바꾸도록 연결해야 한다. 전문가와 진행자, 별도 페어리뷰 연구원의 책임을 구분하되 새로운 승인 절차를 매 단계 만들지 않는다.

## 운영 자문

사람 작업 시간·GPU 관측 시간·단계별 실행 시간은 서로 다른 관측이다. actor/resource별 중복 구간을 합집합으로 계산하고, 계획·남은 예약·관측 실제량을 나눈다. 무료 Colab의 잔량을 만들어내지 않고 마지막 관측 이후는 미확인으로 남긴다. 업로드 요청·영속 저장·다운로드·실제 복구를 각각 확인한다.

초기에는 작은 기록과 단일 진행자로 시작하고, 병렬 갱신이나 트랜잭션이 실제 필요해지면 SQLite 같은 저장 방식을 검토하는 안으로 수렴했다. 자동 Colab 제어·상주 수집기·과금·제출 자동화는 초기 범위에서 제외했다.

## 페어리뷰 자문

공통 기록 기반에 연구/데이터/모델/평가/운영/보고 도메인 계약을 붙이는 구성을 권했다. 검토는 실제 호출과 검토 대상 해시를 연결해야 한다. 역할 지시문 작성은 검토 완료 증거가 아니며, 자기 작성물을 역할명만 바꿔 독립 검토했다고 처리하지 않는다.

기본은 검토 1회와 처분/수정 1회다. 검토자의 새로운 아이디어와 필수 계약 위반을 나누고, 핵심 사실이 달라질 때만 해당 변경을 다시 검토한다. 실패·누수는 관련 행동만 막으며 준비 가능한 다른 연구까지 중단시키지 않는다.
