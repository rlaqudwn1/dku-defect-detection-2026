# 가설·EDA·데이터 계층 설계

2026-11-17 구현 후속: 이 문서의 설계 기준과 당시 미구현 상태는 이력으로 보존한다. 현재 v0.1 실행 명령·지원 범위·실측 한계는 [실행 가이드](RUNBOOK.md)와 소스·테스트를 따른다.

상태: 설계. 현재 관측은 CSV 기본 통계·파일 SHA 검증·JPEG 헤더 크기·동일 바이트 JPG 그룹 0개까지다. 전수 픽셀 디코드·시각 EDA·근접 중복·임베딩·모델 실험은 아직 하지 않았다.

## 1. 가설은 관측에서 실험으로 넘어가는 연결

가설 카드 최소 계약:

```text
질문 ID → 관측 근거와 범위 → 아직 모르는 가정
 → 가능한 설명 → 반증 가능한 예측
 → 비교 후보·고정 변수·평가 대상
 → 주지표·진단 관측·비용 상한
 → 채택·보류·기각 조건 → 다음 행동
```

효과 크기나 시간 기준은 데이터·P000을 본 뒤 실행 전에 고정할 수 있다. 없는 관측을 숫자로 채우지 않는다. EDA에서 가정이 달라지면 가설을 새 버전으로 바꾸고 이유를 남긴다. 최초 아이디어를 끝까지 강제하지 않는다.

초기 질문 예시(채택/검증된 가설 아님):

- 전체 이미지를 줄일 때 판별 정보가 사라지는가? 학습 표본의 원본과 변환을 비교한 뒤 해상도 실험 필요성을 판단한다.
- 크기·제품·배경과 라벨의 관계가 검증을 혼동시키는가? 메타데이터·시각 표본·slice 관측으로 설명의 근거를 찾는다.
- 불균형 보정이 양성 순위에 실제로 도움이 되는가? 양성이 적다는 이유만으로 필요성을 확정하지 않는다.
- 서로 다른 오류가 실제 평균 예측의 개선으로 이어지는가? 오류 차이만으로 ensemble 효과를 단정하지 않는다.

## 2. 질문별 EDA와 결정

| 질문 | 조사와 기록 | 연결되는 결정 |
|---|---|---|
| 모든 입력이 같은 방식으로 읽히는가? | 전수 디코드·CSV 대응·고유 ID·허용 라벨·모드/방향·손상 | 디코더·오류 처리·제외 목록의 필요성 |
| 라벨과 크기·색상·배경이 얽혀 있는가? | 라벨별 메타데이터 표와 표본 ID/관측 | 혼동 요인·오류 분석 slice |
| 단일/복수 제품과 눈에 보이는 결함은? | 표본 추출법·시드·ID·불확실 태그 | 전체 이미지 입력·증강 후보 |
| 전처리가 어떤 정보를 없애는가? | 같은 표본 원본·resize/pad·후보 증강 비교 | 첫 전처리·해상도와 크롭 보류 여부 |
| 독립 표본 가정이 맞는가? | 유사도 후보·사람이 확인한 관계·불확실성 | 촬영 종속 그룹과 분할 |
| train/test 형태 차이의 영향은? | 이미 관측한 크기·비율, 학습 이미지의 변환 민감도 | 보조 스트레스 평가·대표성 한계 |

메타데이터/시각 EDA는 통계 fitting이나 transductive adaptation과 구분한다. 테스트 라벨을 만들거나 외부 원본·공개 정답을 조회하지 않는다. PCA·정규화·fine-tuning처럼 학습하는 변환의 fitting 범위는 별도로 기록한다.

## 3. 데이터 계층별 역할

| 계층 | 내용 | 버전 식별·주의 |
|---|---|---|
| 원본 | 제공 이미지·CSV | 바이트 보존, manifest·SHA-256 |
| 이미지 카탈로그 | ID·상대 경로·역할·원본 라벨·실제 크기/모드·디코드 상태 | 원본 hash와 카탈로그 생성 버전. test label은 null |
| 조사 기록 | 표본 ID·선택 방법·관측·관계 후보·불확실성·결정 영향 | 원본 라벨과 조사 태그 분리. 그룹은 근거로 확정 |
| 결정론적 전처리 캐시 | 실제로 재사용할 resize/pad 등 | 데이터·전처리·생성 코드의 hash. 원본 대체 금지 |
| 임베딩/특징 캐시 | 허용 encoder의 출력과 행 순서 | encoder checkpoint·전처리·ID 순서·shape/dtype·fitting scope |
| 예측 | 모델과 view/fold의 이미지 점수 | 미학습 출처·ID·라벨 방향·split·모델/집계 버전 |
| 보고서 산출물 | 요약표·그림·사례 | 실제 입력 결과·표본 ID와 생성 코드 |

## 4. 캐시를 도입할 때 필요한 계약

`sample_id → feature`의 순서를 추적하고 데이터/라벨/split 버전, 전처리·코드 hash, encoder 가중치의 정확한 출처·hash·공개일·조건, 생성 run과 파일 hash를 기록한다.

- 입력·전처리·encoder·fitting scope가 바뀌면 같은 캐시를 읽지 않는다.
- EDA용 임베딩과 학습 입력용 특징을 용도로 구분한다.
- 허용된 고정 pretrained encoder의 독립 이미지 추출과 데이터에서 학습한 PCA·정규화·fine-tuning은 다르다.
- 검증 이미지를 학습한 encoder의 출력에 OOF라는 이름을 붙이지 않는다.
- 무작위 학습 증강을 하나의 고정 캐시로 바꾸면 실험이 달라진다. 무작위 경로를 캐시했다고 숨기지 않는다.
- 메타데이터·임베딩이 실제 반복 조사나 동결 encoder 학습을 줄일 때만 캐시한다. 캐시 구축비도 예산에 포함한다.

초기에는 이미지 카탈로그와 필요한 파일 캐시를 제안한다. Feast는 batch/offline과 online 특징 관리를 모두 지원하지만 정적 대회 이미지의 그룹·라벨·split을 대신 정하지 않는다. FiftyOne은 표본·임베딩·유사 후보 탐색이 단순 파일/그림으로 어려워질 때 검토할 수 있다. 둘 다 현재 필수 도입으로 확정하지 않는다. [Feast 공식 개요](https://docs.feast.dev/), [FiftyOne Brain](https://docs.voxel51.com/brain/index.html).

## 5. EDA 뒤의 분할 결정

평가가 추정하려는 대상을 한 문장으로 적는다. 제공 학습 분포 내부의 독립 촬영 단위 일반화와 미관측 제품 일반화를 혼동하지 않는다. 제품 종류와 촬영 개체/연속 촬영 그룹은 별개다.

확인한 그룹의 근거·연결 규칙·버전, split별 ID·클래스 수·해시, 파생물의 부모 split 상속, fitting 범위, 미확인 관계와 test 대표성의 한계를 남긴다. 해상도·파일명·유사도만으로 그룹을 자동 확정하지 않는다.

이미지당 라벨 하나이므로 여러 제품·크롭/패치를 사용하면 부모 라벨 보존 문제와 집계 방법을 별도로 검증한다. 첫 기준선은 근거를 갖춘 전체 이미지 경로로 제안한다.

## 6. 완료 조건과 남는 불확실성

- 해시 검증과 픽셀/의미 검증의 결과를 구분한다.
- 각 EDA 질문에 관측 또는 미확인을 적고 분할·전처리·첫 모델 결정에 연결한다.
- 임의 샘플 제외·라벨 덮어쓰기를 하지 않는다. 파생 제외가 필요하면 ID와 이유를 남긴다.
- 정확한 바이트 중복이 없더라도 픽셀 중복·근접 중복·촬영 종속성 부재를 주장하지 않는다.
- 조사 태그·임베딩 유사도·설명용 heatmap을 실제 객체/결함 위치 라벨이나 원인 증거로 승격하지 않는다.

이 조건은 설계 기준이며 현재 EDA가 완료됐다는 선언이 아니다.
