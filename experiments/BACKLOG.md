# 첫 실험 묶음 — 전부 계획 상태

이 목록은 실행 순서 제안이다. 아직 GPU 실측·모델 학습·점수 측정은 수행하지 않았다. 구현 후 각 항목을 개별 카드와 실행 결과로 연결한다.

| ID | 질문·산출물 | 고정할 것 | 다음 판단 |
|---|---|---|---|
| H000 | 어떤 관측이 있어야 첫 모델·전처리·평가를 정할 수 있는가? | 규정·문제 정의·관측/가정 구분 | 가설·반증 예측·EDA 질문 기록 |
| D000 | 파일·이미지·라벨·관계·전처리 보존을 설명할 수 있는가? | 원본 보존·표본 ID·질문별 조사 | 카탈로그와 실제 관측으로 split·입력 결정 |
| V000 | 어떤 일반화를 추정하고 어떤 한계가 남는가? | 확인한 종속 관계·양성 방향·fitting 범위 | split/평가 프로토콜과 작은 튜닝 전 확인 정책 |
| P000 | 무료 Colab에서 실제 1 epoch 학습·검증과 복구가 가능한가? | 첫 후보의 전체 설정, 측정 방법 | 시간·VRAM·복구 결과로 예산 결정 |
| E001 | 전체 이미지 기준 모델의 성능·비용·오류 유형은? | split, seed, 기본 전처리 | 검증 점수와 오류 분석을 다음 실험의 기준으로 저장 |
| E002 | 학습률을 바꾸면 개선되는가? | E001의 나머지 설정, 학습 예산 | 사전 정의한 2~3개 후보를 비교 |
| E003 | 입력 크기와 비율 보존이 결함 인식·비용에 미치는 영향은? | split, seed, backbone, 최적화 | 작은 결함이 보존되는지와 메모리·속도 확인 |
| E004 | 클래스 불균형을 고려한 손실이 도움이 되는가? | 선택한 입력/학습 설정 | 기본 손실과 비교; 가중치는 학습 부분만으로 산출 |
| E005 | 다른 backbone이 다른 오류를 줄이는가? | 같은 split, 비교 가능한 예산 | 원문·라이선스·가중치 공개일 확인 후 두 번째 후보만 우선 검토 |
| E006 | 두 모델의 확률 평균이 더 나은가? | 두 모델의 같은 holdout 예측, 모델 버전 | 단순 평균 우선, 검증 근거가 있으면 제한된 가중 평균 비교 |
| R001 | 선택한 단일/앙상블을 새 세션에서 재현할 수 있는가? | 최종 선택 manifest·환경·수치 허용오차 | 검증 AUROC·확률·제출 형식·해시 검사 |

이 순서를 기계적으로 전부 실행하지 않는다. E001의 오류 분석이나 GPU 예산에 따라 근거를 남기고 보류·변경할 수 있다. 후보를 바꾸면 비교 기준과 상태를 새 기록으로 남긴다.

## 첫 구현의 기능 검사

- 합성 이미지로 학습→검증→테스트 예측→가중치 재로딩 경로를 검사한다. 합성 데이터의 점수는 대회 결과에 넣지 않는다.
- 이미지 ID가 누락·중복·역순인 예측 파일에 대한 검사와 정렬을 확인한다.
- 검증 데이터에 학습 중복 그룹이 섞이면 실패해야 한다.
- 앙상블에서 split·라벨·양성 클래스·구성원 예측 출처가 다르면 실패해야 한다.
- 중단 후 재개에서 epoch, optimizer와 필요한 난수·AMP 상태가 복원되는지 확인한다.
- 단일 클래스 검증셋, 비유한 확률, 범위 밖 확률, 제출 이미지 누락을 성공으로 처리하지 않는다.
- 보고서 집계는 실제 완료 결과만 성능 비교에 사용하고, 서로 다른 split/protocol을 분리하며 실패 상태도 남긴다.
